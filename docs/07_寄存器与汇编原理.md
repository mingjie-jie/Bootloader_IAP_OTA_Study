# 07 | MSP、PSP、CONTROL、VTOR、NVIC：结合原代码学寄存器与汇编

## 1. 向量表前两个字不是代码

```text
APP_IMAGE_BASE = 0x08020000
+0x00 [初始 MSP]         ----> RAM 栈顶
+0x04 [Reset_Handler|1]  ----> APP 复位处理函数地址（Thumb 位）
+0x08 [NMI_Handler|1]
+0x0C [HardFault_Handler|1]
...
```

```c
uint32_t stack = *(volatile uint32_t *)0x08020000;
uint32_t entry = *(volatile uint32_t *)0x08020004;
```

**读取向量表的前两个字并不会“自动跳转”**，它只是从 Flash 取两个整数。只有修改 MSP 并将 PC 分支到入口（例如 `bx r1` 或调用函数指针）才开始执行 APP。

## 2. MSP / PSP 的区别

- **MSP**（Main Stack Pointer）：复位时使用；异常/中断处理在 Handler 模式下一定使用 MSP。
- **PSP**（Process Stack Pointer）：Thread 模式可选；FreeRTOS 普通任务通常使用 PSP。
- **CONTROL.SPSEL**：在 Thread 模式选择 MSP 或 PSP（0=MSP，1=PSP）。
- **CONTROL.nPRIV**：Thread 模式特权级选择（0=特权，1=非特权）。

原代码：

```c
__set_CONTROL(0U);  // Thread 模式使用 MSP，设特权级；不负责把 Handler 变 Thread
__set_MSP(app_stack);
```

如果仍然身处 UART Handler，仅 `CONTROL=0` 不能完成正常异常返回；因此原代码请求**先软件复位**。

## 3. `__disable_irq()` 与 `PRIMASK`

通常对应 ARM 指令：

```asm
cpsid i     ; PRIMASK = 1，屏蔽普通可屏蔽中断
cpsie i     ; PRIMASK = 0，重新允许
```

但它不清除中断**使能寄存器**，也不清除中断**pending**，因此原代码还有 `NVIC->ICER` / `NVIC->ICPR` 两种寄存器操作。FreeRTOS 还会使用 `BASEPRI` 实现优先级阈值屏蔽；直接跳转时也要考虑遗留的 `BASEPRI` 值（经系统复位后通常回到复位状态）。

## 4. NVIC 中断使能与挂起位

```c
NVIC->ICER[i] = 0xFFFFFFFFUL;  // 清除对应外部 IRQ 使能
NVIC->ICPR[i] = 0xFFFFFFFFUL;  // 清除对应外部 IRQ pending
```

`ICER` 和 `ICPR` 是**写 1 清位**类型寄存器，不是向普通 RAM 数组写 `0xFFFFFFFF` 表示“所有中断都启用”。

SysTick 和 PendSV 是**系统异常**，不属于这些外部 IRQ 寄存器覆盖的范围。建议跳转前额外处理：

```c
SCB->ICSR = SCB_ICSR_PENDSVCLR_Msk | SCB_ICSR_PENDSTCLR_Msk;
```

同时清掉外围设备自身中断源（必要时停 UART/DMA/TIM、反初始化时钟）；NVIC 层面的清除不等于外设硬件不再产生新事件。

## 5. `SCB->VTOR`：到底改变了什么？

```c
SCB->VTOR = 0x08020000UL;
```

VTOR 指向当前异常/中断向量表基址。它不改变 CPU 正在执行的 PC，也不修改 Flash 内容，更不会自动装载 APP 的 MSP；这些要分别处理。

例如 UART IRQ 的向量计算可以概念化为：

```text
中断向量表基址 = VTOR
中断向量索引 = 16 + 外部 IRQn
入口地址 = *(uint32_t *)(VTOR + 4 * (16 + IRQn))
```

`16` 个槽是 Cortex-M 核心异常向量（含保留位）所在的前 16 个索引。切换 VTOR 就是告诉 CPU 下一次该从**谁的表**找异常处理函数。

## 6. Thumb 位：为什么 Reset_Handler 地址最低 bit 必须为 1？

Cortex-M7 只支持 Thumb 指令集。函数入口作为向量/指针使用时，其 bit0 表示 Thumb 状态；分支时硬件根据它保持正确指令状态。示例：

```text
向量表保存 0x08022359  （奇数，Thumb 位=1）
实际指令地址 0x08022358
```

原代码 `app_reset & ~1UL` 是**在检查地址范围**时去掉这个状态位，并不是把入口函数指针变成偶数后调用。`app_entry` 使用保留最低 1 的原始入口值。

在 Thumb 平台，跳到 bit0=0 的错误入口可能导致 UsageFault（无效状态）。

## 7. DSB 与 ISB

```c
__DSB(); // Data Synchronization Barrier，数据同步屏障
__ISB(); // Instruction Synchronization Barrier，指令同步屏障
```

- 在发起复位前写 SRAM 请求：需要保证相关写入被适当地提交；
- 在切换 `VTOR` / `CONTROL` 后：指令同步有助于后续执行看到更新后的控制状态；
- **有 D-Cache write-back 时**，单纯 DSB 不一定是把所有待写缓存行显式 Clean 到 SRAM 的代替品。应依据 MPU/Cache 配置验证内存可见性。

## 8. 这份代码最危险的栈切换段

```c
__set_MSP(app_stack);
__DSB();
__ISB();
__enable_irq();
app_entry();
```

编译器对 `MY_OTA_JUMP_JumpNow()` 可能产生如下结构：

```asm
push {r4, r7, lr}        ; 在 Bootloader 的旧 MSP 上建栈帧
...
msr msp, r0             ; 此刻切换为 APP 的 MSP
...
blx r3                 ; 编译器可能访问栈帧/调用辅助代码
```

这种操作会改变 C 函数执行期间使用的栈，**源码层面不能保证绝对安全**。更稳妥的实现是在完全清理并准备好入口后，使用不生成普通函数栈帧的纯汇编末级分支：

```c
__attribute__((naked, noreturn))
void BranchToApp(uint32_t new_msp, uint32_t reset_addr)
{
    __asm volatile (
        "msr msp, r0\n"
        "bx r1\n"
    );
}
```

参数按 ARM AAPCS 常规约定放在 R0（new_msp）、R1（reset_addr）；`MSR MSP,R0` 修改 MSP，`BX R1` 设置 PC 并切换到目标 Thumb 入口。此示例适用于 GCC/ArmClang，需要核对编译器和反汇编；切换前应保证当前处于特权 Thread/MSP 状态。

## 9. 为什么不能在旧 UART IRQ 里直接跳新固件？

进入 IRQ 时，硬件将部分寄存器压入当前线程栈（如 R0–R3、R12、LR、PC、xPSR），CPU 进入 Handler 模式，LR 使用 EXC_RETURN 编码异常返回方式。原中断如果没有按规则完成异常退出，就直接切换 MSP/VTOR，会使**异常现场、返回栈、当前处理模式**不一致。

该源码的设计通过系统复位清空这类旧上下文，再在 `constructor` 中以 Thread 模式处理，是它最重要的架构价值。

## 10. 寄存器速查表

| 寄存器/字段 | 作用 | 与源码对应 |
|---|---|---|
| `MSP` | 主栈指针 | `__set_MSP(app_stack)` |
| `PSP` | 进程栈指针 | FreeRTOS 任务栈，源码未显式设置 |
| `CONTROL` | 特权级、Thread 选用栈 | `__set_CONTROL(0)` |
| `IPSR` | 当前异常编号 | 建议用来确认 Thread 模式 |
| `PRIMASK` | 屏蔽普通可屏蔽 IRQ | `__disable_irq` / `__enable_irq` |
| `BASEPRI` | 中断优先级阈值 | FreeRTOS 常用，源码未处理 |
| `SCB->VTOR` | 异常向量表基址 | 切 APP 向量表 |
| `SCB->ICSR` | 挂起/清除 SysTick、PendSV 等 | 原代码未显式清 Pending |
| `NVIC->ICER[]` | 清除外部 IRQ 使能 | 原代码 for 循环 |
| `NVIC->ICPR[]` | 清除外部 IRQ Pending | 原代码 for 循环 |
| `SysTick->CTRL/LOAD/VAL` | 旧系统节拍控制 | 原代码归零 |
| `SCB->AIRCR.SYSRESETREQ` | 软件系统复位请求 | `NVIC_SystemReset()` 内部机制 |
