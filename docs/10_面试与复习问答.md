# 10 | 面试与复习：30 个高频问题

**Q01. Bootloader、IAP、OTA 有什么区别？**  
Bootloader 是引导程序，IAP 是设备运行时改写程序存储器的方法，OTA 是通过无线网络获取/部署固件的流程。它们可以组合，但不是同义词。

**Q02. 上传代码是否已经是 OTA？**  
不是。它只有跳转请求、软件复位与目标向量表检测，没有任何固件下载或 Flash 擦写代码。

**Q03. STM32H723VE 冷启动从哪里执行？**  
由 BOOT/Option Bytes 选择启动空间；按本学习架构正常从主 Flash `0x08000000` 进入 Bootloader。

**Q04. 向量表第一个字是什么？**  
初始 MSP，不是普通 C 变量、也不是程序第一条指令。

**Q05. 向量表第二个字是什么？**  
`Reset_Handler` 入口（携带 Thumb 位）。

**Q06. 为什么 APP 不能从 main() 直接运行？**  
它还需完成 `SystemInit`、`.data`、`.bss`、C 运行时构造函数等初始化，正确入口是 Reset_Handler。

**Q07. 当前上传头文件的目标地址是多少？**  
`0x08000000`，对应 APP 请求回 Boot 的工程配置。

**Q08. Boot 的 APP 目标地址应该是多少？**  
`0x08020000`，目标上界 `0x08080000`。

**Q09. H723VE 512KB Flash 有几个扇区？**  
4 个 128KB 扇区，Sector0~Sector3。

**Q10. 为什么 `0x08020000` 合适？**  
它位于 Bootloader 占用的第一个 128KB 扇区末尾，恰是 Sector1 的起点。

**Q11. 为什么 SRAM4 保存的是三项而不是一个标志？**  
魔数表明有请求，TARGET 表明方向，反码提供基本一致性检查；可区分 Boot→APP 和 APP→Boot。

**Q12. `volatile` 会保证软件复位后 SRAM4 一定可见吗？**  
不会。它只约束编译器访问优化；链接布局、Cache、MPU、实际复位保留条件仍要检查。

**Q13. `NVIC_SystemReset` 会跳到 0x08020000 吗？**  
不会，它请求系统复位；正常启动目标由 BOOT 配置确定，之后 Bootloader 软件处理 SRAM 请求。

**Q14. 为什么放在 constructor 而不是 UART ISR 直接跳？**  
UART ISR 处于 Handler 模式、异常栈帧尚未结束；复位后从 Thread/MSP 环境重新处理更安全。

**Q15. constructor 如何在 main 前执行？**  
GCC 把函数入口放入初始化数组；ST GCC startup 会调用 `__libc_init_array`，因此在 main 之前运行。

**Q16. Keil 编译器也保证同样的 constructor 行为吗？**  
不保证。应按 Keil 所用启动和 C 运行时核实，必要时改为 main 早期显式检查。

**Q17. `g_pfnVectors` 是什么？**  
ST GCC 启动文件导出的向量表符号，它的地址是当前镜像的向量表地址；不是所有工具链必然有这个名字。

**Q18. `current_address == requested_target` 为什么直接 return？**  
例如 APP 要回 Boot：软件复位已从 `0x08000000` 进入 Boot，此时已经到达目标，无需第二次跳转。

**Q19. 为什么清除 SRAM 请求要放在跳转之前？**  
消费一次性请求，避免再次启动时重复跳转、误循环。

**Q20. `SCB->VTOR` 用来做什么？**  
指定异常和中断的向量表基址，不是设置 PC，也不是执行 Flash 写入。

**Q21. `MSP` 和 `PSP` 区别？**  
MSP 用于复位/Handler，Thread 可选 MSP 或 PSP；FreeRTOS 普通任务常使用 PSP。

**Q22. `CONTROL=0` 是否直接把 IRQ 变成 Thread 模式？**  
不行。Handler→Thread 需要合法异常返回或系统复位，不能用写 CONTROL 代替。

**Q23. 为什么 Reset_Handler 向量地址通常是奇数？**  
最低 bit 是 Thumb 状态标记。对 Cortex-M，必须为 1；取指令范围时可用 `& ~1U` 去除该位。

**Q24. `NVIC->ICER` 和 `NVIC->ICPR` 有何不同？**  
ICER 清除外部 IRQ 的使能，ICPR 清除外部 IRQ 的挂起状态。

**Q25. 清了 NVIC 就不用管 SysTick 和 PendSV 吗？**  
不对。这两个属于系统异常，必要时还应通过 SysTick/SCB 寄存器处理 pending。

**Q26. 为什么原代码的 `__set_MSP` 后继续 C 调用有风险？**  
编译器可能依赖原来的函数栈帧；切换栈后还执行普通 C 语句可能错乱。应采用末级裸汇编分支并核实反汇编。

**Q27. 栈指针只在 SRAM 范围内就完全合法了吗？**  
不是，还应验证对齐、非下边界、实际链接 RAM 布局和足够的栈容量。

**Q28. Flash 里只有 Boot 128KB + APP 384KB，能自动 A/B 回滚吗？**  
不能。内部空间已占满，需要另外保留旧镜像/新镜像或具备可靠的下载恢复路径。

**Q29. CRC32、SHA-256 和数字签名的区别？**  
CRC32 检查传输误码，SHA-256 计算内容摘要，可信签名能验证来源授权；CRC/普通 Hash 本身不能防恶意替换。

**Q30. 面试官问“你做了 OTA”该如何陈述？**  
应明确区分已实际完成的部分与设计扩展，例如：“基于 STM32H723 实现 Bootloader 与 APP 双工程切换，使用 SRAM4 保存跳转请求并通过软件复位进入早期启动阶段；OTA 下载、Flash 安装、校验及回滚是拟集成/已另行实现的部分。”避免把仅有 Jump 模块说成全链路 OTA。

## 一段可背诵的完整逻辑

“STM32 复位后根据启动配置从向量表中取初始 MSP 和 Reset_Handler，然后由启动汇编完成 SystemInit、`.data` 搬运、`.bss` 清零和构造函数调用。我的跳转模块在 SRAM4 保留 12 字节的目标请求，先在运行期间写入请求再发起 SYSRESETREQ。复位后 Bootloader 在 main 前检查并清除一次性请求：如果目标就是 Boot 则继续 main；如果目标是 APP，就校验 APP 的 MSP、Reset_Handler 范围和 Thumb 位，清理旧中断、设置 VTOR 和 MSP，进入 APP Reset_Handler。完整 IAP/OTA 还需要固件接收、Flash 擦写、镜像校验、升级状态、失败恢复和安全签名。”
