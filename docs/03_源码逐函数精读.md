# 03 | 上传的 MY_OTA_JUMP.c/.h 逐函数精读

> 以下逐段说明**完全基于原始文件** `../original/MY_OTA_JUMP.c` 和 `.h`。这里分析的是它**实际会做什么**，并不表示所有写法已达到生产安全要求。问题和建议见 08。

## 1. include 与配置项

```c
#include "MY_OTA_JUMP.h"  // 自定义接口和目标地址宏
#include "stm32h723xx.h"  // STM32H723 寄存器 / CMSIS
#include "stm32h7xx_hal.h"// HAL 依赖
#include "stdio.h"        // 本文件实际未使用，可删
```

原始头文件关键两行：

```c
#define MY_OTA_APP_ADDRESS    0x08000000UL
#define MY_OTA_APP_FLASH_END  0x08020000UL
```

这不是“APP 必须在 0x08000000”，而是**当前工程希望跳到 0x08000000**。因此当前上传头文件对应用于位于 `0x08020000` 的 APP 工程：它需要返回位于 `0x08000000` 的 Bootloader。

在 Bootloader 工程相应改为 `0x08020000 / 0x08080000`，见 `../configs/`。地址上界为**开区间**，判断写的是 `reset_address >= END` 为非法。

## 2. SRAM4 跳转记录

```c
#define JUMP_MAGIC_ADDRESS       0x38003FF4UL
#define JUMP_TARGET_ADDRESS      0x38003FF8UL
#define JUMP_TARGET_INV_ADDRESS  0x38003FFCUL
#define JUMP_MAGIC_VALUE         0x4A554D50UL /* JUMP */
#define JUMP_MAGIC      (*(volatile uint32_t *)JUMP_MAGIC_ADDRESS)
#define JUMP_TARGET     (*(volatile uint32_t *)JUMP_TARGET_ADDRESS)
#define JUMP_TARGET_INV (*(volatile uint32_t *)JUMP_TARGET_INV_ADDRESS)
```

STM32H723 的 SRAM4 地址范围（该器件 16 KiB）是 `[0x38000000, 0x38004000)`，最后 12 字节分配成 3 个 `uint32_t`：

| 地址 | 值 | 意义 |
|---|---|---|
| `0x38003FF4` | `0x4A554D50` | 魔数，告诉新启动的程序“存在跳转请求” |
| `0x38003FF8` | `0x08020000` / `0x08000000` | 本次请求的目标向量表地址 |
| `0x38003FFC` | `~TARGET` | 简易一致性检查，降低随机数据误命中的概率 |

### `volatile` 到底有何作用？

`volatile` 告诉编译器，对这些地址的读取/写入不可像普通局部变量那样优化掉或纯粹用寄存器缓存。**它既不是线程锁，也不保证 Cache 已回写、掉电保存或多字段写入原子性。**

### 为什么不把标志放在普通全局变量里？

普通未初始化全局变量会进入 `.bss`，复位后的启动代码一般将其清零；有初值的全局变量在 `.data` 会被重新初始化。原代码用**固定 SRAM 地址**避开常规 C 数据初始化，但必须在两个工程的链接器里留出末尾 12 字节；若整片 SRAM4 被其他段或栈占用，仍可能被覆盖。

### SRAM4 能否保证复位不丢？

原设计针对的是 `NVIC_SystemReset()` / SYSRESETREQ **软件复位路径**；不是掉电后的持久化存储。不同复位/掉电/低功耗场景需按器件手册验证 SRAM 保持条件。不要用这 12 字节做掉电 OTA 版本状态。

## 3. `extern const uint32_t g_pfnVectors[]`

在 ST 官方 H723 **GCC** 启动文件中存在 `g_pfnVectors` 符号，通常位于 `.isr_vector` 段，它的**地址**就是当前工程链接后的向量表地址。原代码：

```c
extern const uint32_t g_pfnVectors[];
uint32_t current_address = (uint32_t)g_pfnVectors;
```

若当前是 Bootloader，`current_address≈0x08000000`；若当前是 APP，`current_address≈0x08020000`。这里比较的是**当前镜像起始地址**，不是从向量表读取的第一个 MSP 值。

> `g_pfnVectors` 是所选启动文件提供的符号，**不是 ARM 架构强制规定的名称**。Keil 等工具链可能使用 `__Vectors` 等名称；如果发生 undefined symbol，需要核实启动文件并改为匹配的导出符号。

## 4. `MY_OTA_JUMP_IsStackValid()`

```c
if ((address >= 0x20000000UL) && (address <= 0x20020000UL)) return 1U;
if ((address >= 0x24000000UL) && (address <= 0x24050000UL)) return 1U;
if ((address >= 0x30000000UL) && (address <= 0x30008000UL)) return 1U;
if ((address >= 0x38000000UL) && (address <= JUMP_MAGIC_ADDRESS)) return 1U;
return 0U;
```

依次允许 DTCM、AXI SRAM、SRAM1/2、SRAM4。要注意：**这只是区间判断，不保证 SP 对齐、不保证对应 RAM 容量配置和实际使用区域、不保证栈有足够空间**。比如 `address == 0x20000000` 虽被接受，但空栈第一次向下压栈就可能越界；通常初始 MSP 是**RAM 段末尾的对齐地址**。

## 5. `MY_OTA_JUMP_IsApplicationValid()`

```c
uint32_t app_stack = *(volatile uint32_t *)MY_OTA_APP_ADDRESS;
uint32_t app_reset = *(volatile uint32_t *)(MY_OTA_APP_ADDRESS + 4UL);
uint32_t reset_address = app_reset & ~1UL;
```

- `*BASE`：取目标向量表第一个字 = APP 初始 MSP。
- `*(BASE+4)`：第二个字 = APP Reset_Handler 地址。
- `app_reset & ~1UL`：清除最低位 `Thumb` 状态标记，获得可用于 Flash 范围比较的实际指令地址。

随后三道判断：

1. `app_stack` 在允许的 SRAM 地址区间；
2. `reset_address` 在 `[MY_OTA_APP_ADDRESS, MY_OTA_APP_FLASH_END)`；
3. `app_reset & 1UL` 必须为 1（Cortex-M7 的 Thumb 状态要求）。

**只要三项都符合就返回 1**。它不校验固件 CRC、长度、版本、数字签名。随机的错误数据也可能碰巧满足，真正 OTA 需增加完整镜像校验。

## 6. `MY_OTA_JUMP_JumpNow()`：各语句细读

### 步骤 A：先验证再取向量

```c
if (MY_OTA_JUMP_IsApplicationValid() == 0U) return;
app_stack = *(volatile uint32_t *)MY_OTA_APP_ADDRESS;
app_reset = *(volatile uint32_t *)(MY_OTA_APP_ADDRESS + 4UL);
app_entry = (MY_OTA_JUMP_EntryFunction)app_reset;
```

- 先阻止明显非法的 APP；
- 由第一个 32 位向量恢复 MSP；
- 由第二个向量得 Reset_Handler，转换为函数指针。

### 步骤 B：全局屏蔽中断

```c
__disable_irq();
```

CMSIS 通常编译为 `CPSID i`，设置 `PRIMASK=1`，屏蔽普通可屏蔽中断；不是关闭时钟，也不是停止所有 Fault/NMI。

### 步骤 C：关闭 SysTick

```c
SysTick->CTRL = 0U;
SysTick->LOAD = 0U;
SysTick->VAL = 0U;
```

`CTRL` 控制使能/中断，`LOAD` 是重装值，`VAL` 是当前计数。停止旧镜像留下的系统节拍，减少 APP 还未准备好时错误触发中断的风险。若已存在挂起的 SysTick，需**额外清理挂起位**，原代码没有显式处理 `SCB->ICSR.PENDSTCLR`。

### 步骤 D：禁用并清除 NVIC 外部中断

```c
for (index = 0U; index < 8U; index++) {
    NVIC->ICER[index] = 0xFFFFFFFFUL;
    NVIC->ICPR[index] = 0xFFFFFFFFUL;
}
```

- `ICER`：Interrupt Clear-Enable Register，清中断使能位。
- `ICPR`：Interrupt Clear-Pending Register，清中断挂起位。
- 每个 32 位寄存器对应 32 个外部 IRQ，8 组最多覆盖 256 个编号。
- **NVIC 外部中断 ≠ SysTick/PendSV 等系统异常**，它们由 SCB/SysTick 单独管理；更不等于清掉 UART/DMA 外设自己的中断源和标志。

### 步骤 E：更换中断表

```c
SCB->VTOR = MY_OTA_APP_ADDRESS;
```

这是最容易遗漏的一行。后续异常发生时，内核要从 **APP 向量表**而不是 Bootloader 向量表读取处理函数入口。注意目标 `SystemInit()` 也可能重写 VTOR。

### 步骤 F：Thread 模式使用 MSP

```c
__set_CONTROL(0U);
__DSB();
__ISB();
```

`CONTROL=0` 对 Thread 模式意味着使用 MSP，并尝试处于特权级；它**不能把当前 Handler 模式直接切成 Thread 模式**。正因为如此，源码选择先在 IRQ 内请求复位，再在新启动的构造函数里跳转。

- `DSB`：数据同步屏障，保证先前相关存储操作完成；
- `ISB`：指令同步屏障，保证后续执行看到新的控制/上下文配置。

### 步骤 G：设置目标 MSP 并分支

```c
__set_MSP(app_stack);
__DSB();
__ISB();
__enable_irq();
app_entry();
```

意图是：装载目标主栈、启中断、运行 APP Reset_Handler。

**这里是必须特别警惕的一段**：改变 MSP 后，普通 C 编译器仍可能生成访问原函数栈帧的指令，甚至在 `app_entry()` 调用过程中使用栈。同时过早 `__enable_irq()` 也有风险。不要仅凭“设置 MSP 后不写局部变量”就保证汇编安全。`../examples/safer_jump_gcc.c` 给出**只针对 GCC/Clang 的参考分支方式**，需要结合工程反汇编和实机调试。

## 7. `MY_OTA_JUMP_CheckRequestAfterReset()`

```c
__attribute__((constructor))
static void MY_OTA_JUMP_CheckRequestAfterReset(void)
```

该函数如果被启动文件执行 `__libc_init_array()` 调用，就在 `main()` **之前**运行。

执行顺序：

1. 取 `current_address = g_pfnVectors`（当前镜像向量表基址）；
2. `MAGIC == JUMP_MAGIC_VALUE` 且 `TARGET_INV == ~TARGET` 才认定请求有效；
3. 先复制 `TARGET` 到局部变量，再**清除**三个 SRAM4 字段；
4. 目标是当前镜像：继续进入当前 `main()`；
5. 目标是本工程配置的**另一镜像**：调用 `MY_OTA_JUMP_JumpNow()`；
6. 其余情况：不跳转，继续当前 `main()`。

提前清除是**一次性请求**的关键：否则 APP 再启动时可能再次看见请求，产生错误循环。注意清除之前已通过检查；在写请求那端应考虑**MAGIC 最后写入**，详见 08。

## 8. `MY_OTA_JUMP_Request()`

```c
if (MY_OTA_JUMP_IsApplicationValid() == 0U) return;
JUMP_MAGIC = JUMP_MAGIC_VALUE;
JUMP_TARGET = MY_OTA_APP_ADDRESS;
JUMP_TARGET_INV = ~MY_OTA_APP_ADDRESS;
__DSB();
__ISB();
NVIC_SystemReset();
while(1) {}
```

这里的核心是**记录目标 → 软件系统复位**。调用点可以在 UART 中断回调里，因为它**不是在中断里直接改 MSP 跳程序**。成功触发系统复位一般不返回。

`NVIC_SystemReset()` 通过 AIRCR.SYSRESETREQ 请求系统复位；它**不等价于修改 BOOT 引脚、Option Bytes 或让硬件直接从 APP 运行**。

原代码的一个微小但真实的可靠性问题：它先写 `MAGIC` 再写目标和反码。若重启/异常恰好插在写入中间，可能读取到半完成记录。应优先写 `TARGET` 与 `~TARGET`，最后写 `MAGIC`，并考虑 Cache 和原子性。

## 9. 把函数关系背下来

```text
业务/UART 回调
  └─ MY_OTA_JUMP_Request
       ├─ MY_OTA_JUMP_IsApplicationValid
       ├─ 写 SRAM4 标志
       └─ NVIC_SystemReset
            └─ 默认启动工程的 Reset_Handler
                 └─ __libc_init_array
                      └─ MY_OTA_JUMP_CheckRequestAfterReset
                           ├─ 无请求/目标已是当前工程 -> main
                           └─ 请求其他工程
                                └─ MY_OTA_JUMP_JumpNow
                                     ├─ MY_OTA_JUMP_IsApplicationValid
                                     └─ 目标 Reset_Handler -> main
```
